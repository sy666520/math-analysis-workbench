# 分析工作台 · 设计文档

> 选题 C4：数学分析学习工作台 —— 把知识导航、AI 助教、绘图计算、错题本整合到一个界面
> 交付要求：工作台（≥2 个模块）+ 源代码 + 设计文档 + 演示视频 3–5 分钟

---

## 一、为什么做这个

任务书对 C4 的定义是"把知识导航、AI 助教、绘图计算、错题本等整合到一个界面"。但"整合"两个字很容易做成四张卡片摆在一起，点进去各干各的。我们想回答一个更具体的问题：

**学生在数学分析里卡住的时候，到底是卡在哪一步？**

拆开来看，几乎总是三件事之一：

1. **不知道用哪个工具**——手上有洛必达、泰勒、等价无穷小，但不知道什么时候该用哪个，因为记不清它们的前提；
2. **算出来了但不敢信**——极限是 1 还是 −1，画个图确认一下，但课本上的图是静态的；
3. **错了但记不住为什么错**——抄一遍正确答案，下次还在同一处断掉。

这三件事分别对应"条件"、"图像"、"错因"。所以工作台的设计原则是：**每个模块只负责把一件事讲清楚，且必须能回答"为什么"，而不只是"是什么"。**

这也决定了我们不做成题库、不做成视频课。题库解决"量"，我们想解决"卡点"。

---

## 二、五个模块与它们的职责边界

| 模块 | 回答的问题 | 关键设计 |
|---|---|---|
| 知识图谱 | 这个知识点**依赖什么**？成立**要什么条件**？**哪里会错**？ | 卡片强制分栏：条件 / 易错 / 反例，缺一不写 |
| 函数实验室 | 我的**直觉**对不对？ | 左右逼近表 + 病态函数预设，把"接近"变成可读的数字 |
| 定理检验 | 这条定理**现在到底能不能用**？ | 逐条数值检验前提，条件不满足时明确区分"不能用"与"结论错" |
| 错题本 | 我上次**断在哪一步**？ | 只记错因与纠正依据，不记答案；间隔重复排期 |
| AI 助教 | 我该去**看哪张卡片**？ | 检索而非生成，每条回答标注命中来源 |

五个模块之间不是并列关系，而是有数据流：知识图谱是索引，实验室和定理检验是它的"验算器"，错题本从任意卡片一键挂载，助教反向指回卡片。

## 三、总体架构

```
index.html                 静态骨架：五个 <section class="view">
      │
      ├── app.js            路由 / 卡片详情渲染 / KaTeX 行内公式 / 设置
      │
      ├── knowledge.js      【数据层】39 张卡片、50 条依赖、关键词索引
      │
      ├── expr.js           【计算层】表达式解析 → 求值 → 数值分析工具
      │        │
      │        ├── plot.js  【绘图层】Canvas 引擎：刻度、断点、交互
      │        ├── lab.js         模块 2
      │        └── theorem.js     模块 3
      │
      ├── graph.js          【可视化层】SVG 知识图谱
      ├── mistakes.js       【持久层】localStorage + 间隔重复
      └── tutor.js          【检索层】倒排式打分 + 意图路由（可选在线模型）
```

**分层意图**：`expr.js` 不知道任何 UI 的事，只暴露 `compile / deriv / integrate / scanRoots`。实验室和定理检验共用同一套数值工具，因此"实验室里看到的导数"和"定理检验里判断可导用的导数"是同一个算法，不会自相矛盾。这一点在答辩时被问到"两个模块的结论为什么不一致"时很重要——它们不可能不一致。

**为什么不用框架**：任务书要求"含 index.html 的文件夹（可离线打开）"。React/Vue 需要 CDN 或构建产物，前者断网即失效，后者增加交付复杂度。全部原生实现约 3200 行，无构建、无依赖。

**唯一的外部件是 KaTeX**：公式排版手写达不到教材质量，而 KaTeX 可以整体内嵌（含 woff2 字体，600 KB），断网照常渲染。这是有意识的取舍——把"离线"这条硬约束守住，只在一个不影响离线的地方引入依赖。

## 四、数据模型

### 4.1 知识卡片

```js
{
  id: 'n19', ch: 'c3',
  title: '洛必达法则及其失效',
  sub: '三个条件',            // 图上的一行副标题
  level: 'core',              // core / adv，决定图上色条
  formula: String.raw`\lim\frac{f}{g}=\lim\frac{f'}{g'}`,
  idea: '一句话定位……',
  cond:  ['必须是 0/0 或 ∞/∞ 型', …],   // 成立条件
  traps: ['不是未定式就用', …],          // 常见错误
  counter: '$\\lim (x+\\sin x)/x = 1$ …',  // 反例 / 陷阱实例
  deps: ['n18']               // 前置依赖
}
```

字段是**强制性的写作约束**：定理类卡片必须写 `cond`，有反例的必须写 `counter`。目前 39 张卡片中 18 张有明确条件清单、11 张带具体反例、共 108 条易错点。写作时反复遇到的情况是"这个点我讲不清条件"——那就说明我没真懂，回去查书。

`deps` 构成有向无环图（50 条边），图谱布局直接由它生成，同时也是助教做"相关知识点"推荐的依据。

### 4.2 错题记录

```js
{ id, title, wrong, right, tag, level, created, stage, next }
```

`stage` 是复习阶段 0–5，对应间隔 `[1,2,4,7,15]` 天。"记住了"则 stage+1 并把下次复习推后，"还得再看"则 stage−1 并明天再见。这是最简的间隔重复，够用，不必上 SM-2。

`tag` 指向知识卡片 id，于是"按章节分布"的统计和"这道错题属于哪个知识点"能自动对上。

## 五、关键实现

### 5.1 表达式解析（expr.js）

不用 `eval`，自己写词法分析 + 递归下降：

```
expr   := term (('+'|'-') term)*
term   := unary (('*'|'/') unary)*
unary  := ('-'|'+') unary | power
power  := primary ('^' unary)?        // 右结合
primary:= number | ident '(' expr ')' | ident | '(' expr ')'
```

两个细节值得说：

- **隐式乘法**：`2x`、`3sin(x)`、`x(x+1)` 都要能识别。做法是在词法阶段扫描相邻 token，当"前一个能结束一个因子"且"后一个能开始一个因子"时插入 `*`。但函数名后跟左括号是**调用**不是乘法，必须排除，否则 `sin(x)` 会变成 `sin*(x)`。
- **一元负号的优先级**：按 `-2^2 = -(2^2) = -4` 处理。实现上是 `unary` 调用 `power`，而 `power` 的指数位置又回到 `unary`，这样既保证 `^` 右结合（`2^3^2 = 2^9`），又保证负号低于乘方。这两条在写测试时都验证过。

### 5.2 数值工具（expr.js）

| 工具 | 方法 | 说明 |
|---|---|---|
| 导数 | 中心差分 `(f(x+h)−f(x−h))/2h`，h=1e-5 | 误差 O(h²)，对绘图与读数量级足够 |
| 二阶导 | 二阶中心差分，h=1e-4 | h 取大一点以抑制舍入误差 |
| 积分 | 自适应 Simpson，容差 1e-8，递归深度 20 | 光滑函数收敛极快 |
| 求根 | 采样扫描变号 + 二分细化 60 次 | 用于定位 ξ 与零点 |

**一个真实踩到的坑**：`x²sin(1/x)` 在 `x=0` 处无定义（可去间断），自适应 Simpson 的采样点恰好包含 0，于是整个积分返回 NaN，界面显示"未定义"。这在数学上不算错，但会误导——该函数在 [−1,1] 上可积且积分为 0。解决办法是加一条回退路径：Simpson 结果为非有限值时，改用**复合中点法**（n=2000），中点永不落在端点上，从而绕开可去奇点。回退后积分返回 2.98×10⁻¹⁷ ≈ 0，与"奇函数在对称区间积分为零"一致。

### 5.3 绘图引擎（plot.js）

- 刻度步长取 `1/2/5 × 10^k`，保证标签是"好看"的数
- 采样密度取画布宽度的 2 倍，遇到 `NaN` 或 `|y| > 1e7` 时**断开折线**，避免把 `tan x` 的渐近线连成一条竖线
- 裁剪用 `ctx.clip()` 而非逐点判断，性能更好也不会画出界
- 交互：拖拽平移、滚轮以光标为中心缩放、双击复位

滚轮缩放要以**光标位置为不动点**，否则放大时目标会飘走：

```js
const k = e.deltaY > 0 ? 1.12 : 1/1.12;
const mx = invX(e.offsetX), my = invY(e.offsetY);
setRange(mx + (xmin-mx)*k, mx + (xmax-mx)*k, ...);
```

### 5.4 知识图谱布局（graph.js）

难点是**宽度自适应**。最初做成"一章一行"，但第 1 章有 9 个节点，一行铺开需要 1700 px，右侧详情面板挤压后大量节点被裁到视口外，观感很糟。

改为**带内自动换行**：

```
对每一章：
  依次放置节点，若 x + w > 可用宽度 则换行
  带高 = 10 + 行数 × 64 + 4
```

宽度在 `build()` 时从容器 `clientWidth` 读取，窗口 resize 时防抖 180 ms 重建。这样无论投影仪是 1280 还是 1920，图谱都刚好铺满，不出现横向滚动条。

依赖边用三次贝塞尔，分三种情形：同行向右（水平弧）、跨行向右下（S 形）、跨行向左（大回环，控制点外扩 58 px 避免穿过节点）。悬停或选中某节点时，只有与它直接相连的边高亮，其余淡化到 12%。

### 5.5 定理条件检验（theorem.js）

这是全篇最需要小心的地方。检验流程：

1. **连续性**：在 [a,b] 取 400 个采样点，检查是否存在非有限值；再检查相邻差分的最大值是否超过中位数的 60 倍（跳变检测）。
2. **可导性**：对每个内点分别算**左差商**与**右差商**，若两者相对偏差超过 12%，判定为尖点。这里不能用对称差商——`|x|` 在 0 处对称差商恒为 0，会得出"可导"的错误结论。
3. **端点值 / 分母**：直接比较 `f(a)` 与 `f(b)`，以及 `g(b)−g(a)` 是否为 0。
4. **求解 ξ**：对 `f'(x) − k` 做变号扫描 + 二分。

**必须处理的一个假阳性**：用 `|x|` 检验罗尔定理时，变号扫描在 `x≈0` 处发现 `f'` 从 −1 跳到 +1，于是判为"根"，报告"存在 ξ=0 使 f'(ξ)=0"。但 `f` 在 0 处根本不可导，这个 ξ 是数值假象。

修正是**在候选点再做一次尖点判定**：

```js
const hh = (b-a)*1e-4;
const dl = (f(x)-f(x-hh))/hh, dr = (f(x+hh)-f(x))/hh;
// 左右导数不一致 → 不可导 → 该 ξ 无效
return Math.abs(dr-dl) <= 0.02*(1+Math.abs(dl)+Math.abs(dr));
```

修正后，`|x|` 的例子如实报告"未找到满足结论的点"，并解释"这正是可导条件不能去掉的原因"——反而成了一个更好的教学案例。

**设计上最关键的一点**：条件不满足时，界面**不会**说"结论错误"，而是说"本定理不能直接使用"，然后**继续报告实际观察**（是否仍存在 ξ）。因为中值定理的条件是充分非必要，把"条件不满足"等同于"结论不成立"是学生最常见的逻辑错误，工具不能强化它。

### 5.6 检索式助教（tutor.js）

先说明它的性质：**这不是大模型，是一个可解释的检索器**。原因见第七节。

流程是三步：

1. **分词**：英文按词切；中文按二元组（bigram）切，去停用词。中文不加词典也能拿到可用的召回，代价是"可导"会被切成"可导"+"导一"等噪声，靠后续打分压掉。
2. **打分**：标题命中 +14、副标题 +6、定位 +5、易错 +4、条件 +3、反例 +3、公式 +2。另外维护一张关键词索引表（`KB.kw`），把"洛必达""罗尔""雅可比"这类**术语**直接映射到卡片，命中 +18——因为口语提问常常不出现标题里的字面词（问"雅可比因子为什么是 r"，标题是"极坐标变换与雅可比"）。
3. **意图路由**：根据问句里的词判断类型，再决定组织哪部分内容：
   - 含"为什么/错/反例/失效" → 先给成立前提，再给易错点与反例
   - 含"条件/前提/什么时候/能不能用" → 给条件清单
   - 含"怎么/如何/求" → 给定位 + 前提 + 踩坑
   - 含"区别/不同" → 给对比要点

每条回答底部列出命中的卡片（可点击跳转到图谱对应节点），这是"可追溯"的具体含义：**用户永远能知道这个答案是从哪张卡片来的**，而不是接受一个无法核查的断言。

### 5.7 错题本（mistakes.js）

- 排序按 `next` 升序，到期的排在最前并标红左边框
- 每张卡片只展示两栏：「错在哪一步」与「纠正依据」，不展示答案
- 统计四个指标：总数、今日待复习、已进入长周期（stage≥3）、涉及知识点数
- 按章节的分布用条形图，颜色直接取该章在图谱里的色值，与模块 1 视觉上连续

### 5.8 响应式与移动端（style.css / graph.js / plot.js）

移动端不是把桌面布局等比缩小，而是换了一套交互模型：

| 桌面 | 手机（≤ 860px） |
|---|---|
| 左侧竖向模块栏 | 底部标签栏（五格，含安全区适配） |
| 各视图 `height:100%`、内部滚动 | 整页自然滚动，`100dvh` 处理地址栏收展 |
| 知识图谱为有向图（可横向拖动） | 改为按章分组的纵向列表，点行即看详情 |
| 实验室：左控制栏 + 右绘图 | 函数输入 → 图 → 参数 → 数值，一节一节往下 |
| 鼠标拖动 / 滚轮缩放 | 单指拖动平移、双指捏合缩放（缩放锚点在双指中点） |

几个必须踩过的坑：

1. **`100vh` 在手机浏览器上会溢出**（地址栏把可视高度吃掉一截），改用 `100dvh`。
2. **嵌套滚动容器在触屏上很难滚**——桌面版每个面板各自 `overflow:auto`，手机上全部改为让 `.views` 这层统一滚动，只有对话框保留内部滚动（聊天场景的自然预期）。
3. **图谱压到手机宽度会退化成两三个字的方块**：39 个节点排布需要约 658px，塞进 390px 必然要靠横向拖动对位，实测很难点准。所以窄屏直接换列表，搜索框共用同一套 `filter()` 逻辑。
4. **输入框字号必须 ≥16px**，否则 iOS Safari 聚焦时会自动放大整个页面。
5. **图表手势要 `touch-action: none` + `preventDefault`**，否则单指拖图会变成滚动页面。
6. **初始化时的自动滚动会串页**：助教开场白会调用"滚到底"，若此时用户还在别的模块，整页会被拉到底部。修法是视图未激活（`offsetParent === null`）时直接返回。

## 六、数学正确性怎么保证

课程的核心立场是"数学内容的正确性由你们负责"，所以这部分写得细一点。

**1. 每条反例都单独验算。** 例如「沿所有直线趋于同值也不能断定二重极限存在」用的 `f = xy²/(x²+y⁴)`：沿 `y=kx` 时 `f = k²x/(1+k⁴x²) → 0`；沿 `x=y²` 时 `f = 1/2`。两个结果都手算复核过。卡片里的 11 个反例全部经过这一步。

**2. 承认并修正自己的错误。** 初稿在罗尔定理的卡片里写「`|x|` 在 [−1,1] 上条件不满足但结论仍成立」，这是**错的**——`(−1,1)` 内 `f'≡±1` 处处非零，根本不存在 `f'(ξ)=0`。这个错误是在做定理检验模块、让程序去找 ξ 时暴露出来的：程序找不到根，与卡片文字矛盾，回头验算才发现卡片写错了。这条记录已写入 AI 使用日志的纠错表。

**3. 数值结论必须标明性质。** 实验室的逼近表下方写"数值上强烈提示极限存在（教材上仍须给出 ε-δ 证明）"；定理检验面板底部写"这是经验证据，可作为理解工具，不能替代课堂上的严格证明"。工具不该假装自己是证明。

**4. 不做无把握的推断。** 数值积分遇到真奇点返回"未定义"而不是强行给数；`1/x` 在 [−1,1] 上判为不连续并明确说明原因，而不是悄悄跳过。

## 七、AI 助教为什么不是大模型

这是设计上最需要解释的一个决定。

任务书鼓励用 AI，但同一份任务书也写着"AI 负责做出来，你们负责讲清楚、验得对、找出 AI 的错"，并且要求提交"AI 出错—如何发现—如何纠正"的记录。

如果助教直接调用大模型，会有三个问题：

1. **离线不可用**。答辩现场网络不可靠，一个需要 API Key 的核心模块是演示风险。
2. **不可追溯**。模型给出的定理条件可能是拼凑的，而学生没有能力当场判断真假，这与课程立场相反。
3. **无法自证**。评分要的是"你能控制 AI"，而不是"你接了个 API"。

所以我们做的是一层**检索 + 意图路由**：答案的每一句都来自人工校对过的卡片，命中来源直接标在回答下方。它的能力边界很清楚——找不到就直说找不到，绝不编造。这个"不编造"是写进系统提示和代码里的：匹配分低于阈值直接返回"没有找到足够接近的卡片"。

同时保留了**可选的在线模式**：在设置里填入任意 OpenAI 兼容接口，助教会把检索到的 3 张卡片作为上下文发给模型润色。此时界面上会明确标注"在线模型 + 本地检索"，调用失败自动回退到本地，不会白屏。这个设计的用意是：在线是增强，不是依赖。

## 八、已知局限与后续

| 局限 | 说明 | 可能的改进 |
|---|---|---|
| 判定是数值的 | 采样可能漏掉极窄的间断或尖点 | 引入符号求导做交叉验证 |
| 只支持一元函数 | 多元曲面不在本工具范围 | 用 WebGL 做 3D 曲面模块 |
| 无符号积分 | 只能数值积分 | 接 CAS 或手写模式匹配 |
| 助教不理解语义 | 词面匹配，同义改写会漏召回 | 加小型向量检索或本地 embedding |
| 错题本无图片 | 纯文本记录 | 支持粘贴截图（IndexedDB） |

这些都写进文档而不是藏起来——一个工具知道自己不知道什么，比它多会一个功能更重要。
